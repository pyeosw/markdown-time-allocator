# 作業時間の配分

Markdownの日別記録から実働時間を計算し、作業項目へ0.25h単位で配分するVSCode拡張です。

## 使い方

1. Markdownの対象日の見出し1、またはその本文にカーソルを置きます。
2. コマンドパレットまたは右クリックメニューから「作業時間を配分」を実行します。
3. 必要に応じて勤務区分を「AM休暇」に切り替え、各項目の「＋」「−」で時間を配分します。
4. 「適用」でMarkdownに時間行を追加・更新します。保存はVSCodeの通常の保存操作・自動保存設定に従います。

```md
# 20261028

## 案件A

### 作業A
- 調査

### 作業B
- 実装

## 案件B
- 打ち合わせ

## 時間
- 18:00
```

既定設定では、作業A・作業B・案件Bが配分対象になります。始業09:00、昼休憩1時間、退勤18:00なら実働8hです。残時間は「その他」へ自動配分し、`## 時間`の直前に配置します。既存のその他にメモがある場合も保持して移動します。

出力した時間行には管理用コメントが付きます。同じ値で再適用しても行は増えず、通常のUndoで適用を取り消せます。

```md
- 作業時間: 1.25h <!-- time-calculator:duration -->
```

## 設定

ユーザー設定・ワークスペース設定・フォルダー設定で指定できます。

```json
{
  "timeCalculator.startTime": "09:00",
  "timeCalculator.breakTimes": ["12:00-13:00", "20:00-20:30"],
  "timeCalculator.amLeaveStartTime": "13:00",
  "timeCalculator.maxHeadingDepth": 6
}
```

- 見出しの最大深さは2〜6です。2なら案件単位、3なら作業単位など、上限内で末端となる見出しへ配分します。
- 重複した休憩は一度だけ控除し、勤務時間に重なる部分のみ差し引きます。
- 休憩控除後の合計を15分単位へ丸めます。15分で割った端数が7分以下なら切り捨て、8分以上なら切り上げます。
- 配分の超過は負の残時間で表示し、適用を禁止します。
- 文書や設定を変更した後は「再読込」が必要です。深さの設定変更で既存の管理行が対象外になる場合は、その行を整理してから適用してください。

日付をまたぐ勤務は扱いません。勤務区分はパネルを閉じると通常に戻るため、AM休暇の日は開くたびに選択してください。対象ブロックには`## 時間`とプレーンテキストの退勤時刻を1つずつ置いてください。

## インストールと開発

VSCode 1.95以降に対応します。開発にはNode.js 22.12以降とnpmを使用します。

CIと依存関係の解決方法をそろえるため、開発時は`.nvmrc`に記載したNode.js 22.23.4と、その付属のnpm 10.9.9を使用してください。npmのバージョンは`package.json`の`packageManager`にも記載しています。依存関係を変更した場合は、この環境で`npm install`を実行して`package-lock.json`を更新し、`npm ci`が成功することを確認して両ファイルをコミットしてください。

```sh
npm ci
npm run test:ci
```

`npm run test:ci`はGitHub Actionsと共通の事前確認コマンドです。型チェック、書式チェック、単体・画面テスト、VSCode統合テスト、VSIX生成を順に実行し、途中で失敗した場合は停止します。プッシュ前に上記2コマンドを実行してください。GitHub固有の権限・通信や成果物アップロードまでの成功を保証するものではありません。

書式チェックで失敗した場合は`npm run format`で整形してから、`npm run test:ci`を再実行してください。`.gitattributes`とPrettierの`endOfLine`設定でテキストの改行をLFに統一し、WindowsのチェックアウトでもCRLFへ変換されないようにしています。既存の作業フォルダーにCRLFのファイルが残っている場合も、`npm run format`でチェック対象のファイルを整えられます。

各工程を個別に実行する場合は、`npm run check`、`npm run check:format`、`npm test`、`npm run test:integration`、`npm run package`を使用します。ビルドだけなら`npm run build`を実行してください。

`npm run test:integration`は公式のテスト用VSCodeを取得し、プロジェクト内の専用プロファイルでMochaを実行します。インストール済みVSCodeで実行する場合は環境変数`VSCODE_EXECUTABLE_PATH`に実行ファイルの絶対パスを設定します。単体テストと配分画面のDOMテストにはVitestを使用します。

VSCodeでこのフォルダーを開いてF5を押すと、Extension Development Hostを起動できます。拡張の動作確認用Markdownを開き、上記コマンドを実行してください。

`npm run package`で`artifacts/time-calculator-vsc-0.1.0.vsix`を生成します。VSCodeの拡張機能画面の「VSIXからのインストール」で導入できます。ローカル配布用の仮のpublisherを使用しています。Marketplaceへの公開は行いません。

設計の詳細は、ソースフォルダーの`docs/設計仕様.md`を参照してください。
