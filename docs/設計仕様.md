# 設計仕様

## 1. 目的と対象範囲

[要求仕様](要求仕様.md)とレビューコメントを基に、Markdownの見出し1で区切られた日別の記録に対して、実働時間の計算、項目への時間配分、Markdownへの反映を行うVSCode拡張を設計する。

本書は初期実装の設計であり、既存実装を説明するものではない。対象は編集中のMarkdown文書とし、保存前の編集内容も解析する。外部サービスへの送信や複数日分の一括配分は対象外とする。

### 2.2. 要求の補足と設計上の決定

以下はレビューコメントの反映と要求への追加解釈を含む、初期実装の動作方針である。

| 論点 | 設計上の決定 |
| --- | --- |
| 親見出しと子見出しの配分 | 設定した最大深さまでの見出しツリーで末端となる見出しだけに配分する。上限より深い見出しは、その配分対象の内訳として保持する |
| 見出しの最大深さ | `timeCalculator.maxHeadingDepth`で2〜6を指定する。既定値は6とする |
| 「別画面」の形式 | VSCode内のWebviewパネルをエディターの横に表示する |
| AM休暇の判定 | 日付や本文から推測せず、配分画面で「通常／AM休暇」を選択する |
| その他の編集 | その他は残時間の表示専用とし、カウンターを設けない |
| その他の配置 | 適用時に`## 時間`の直前へ配置する。既存のその他が別の位置にある場合は本文ごと移動する |
| 時間行の識別 | HTMLコメントの管理マーカーを付け、再適用時に同じ行を更新する |
| 15分単位に合わない実働時間 | 休憩控除後の合計に対し、15分で割った端数が7分以下なら切り捨て、8分以上なら切り上げる |
| 日付をまたぐ勤務 | 初期実装では扱わない。退勤時刻が始業時刻以前ならエラーにする |
| 配分の初期値 | 既存の管理用時間行があれば復元し、なければ0hにする |
| 0hの出力 | 通常項目は0hも出力する。その他の見出しの新規作成条件は8.3節に従う |
| 適用と保存 | 適用はエディターの内容を更新する。ディスク保存はVSCodeの保存操作・自動保存設定に従う |

## 3. 起動方法と対象ブロック

1. ユーザーがMarkdownエディターで対象日の見出し、またはその本文にカーソルを置く。
2. コマンドパレットまたはエディターのコンテキストメニューから「作業時間を配分」を実行する。コマンドIDは`timeCalculator.allocate`とする。
3. 拡張はアクティブなMarkdown文書と、主選択範囲のアクティブ位置を取得する。
4. その位置を含む見出し1のブロックを特定し、配分画面を開く。

ブロックは見出し1の開始位置から、次の見出し1の直前、または文書末尾までとする。次の見出し1の行上にカーソルがある場合は、その見出しのブロックを選ぶ。見出し1より前の前書きは対象に含めない。見出し1の文字列は画面タイトルとして使い、`YYYYMMDD`形式の必須チェックや日付計算は行わない。

非Markdown文書、アクティブエディターなし、対象となる見出し1なしの場合は、理由を通知して終了する。複数カーソルの場合も主選択だけを使用する。

パネルは拡張全体で1つとし、文書URIと選択したブロックに固定する。エディターのカーソル移動だけでは対象を切り替えない。同じ対象で再実行した場合はパネルを前面に出して入力を保持する。別の対象で再実行した場合、未適用の入力があれば切り替え確認を行う。破棄を選択した場合だけ新しい対象を読み込む。

## 4. Markdown解析

### 4.1. 構造の認識

CommonMarkに対応し、ソース位置を取得できるMarkdownパーサーを用いる。単純な行頭の正規表現だけで見出しを抽出しない。ASTの文書直下にある見出しを対象とし、コードブロック、引用、箇条書き、HTMLブロック内の見出しに見える文字列は対象外とする。ATX形式とSetext形式の見出しを扱う。

見出しの階層はレベルから構成する。レベルが飛んだ場合も、直前にある自分より浅いレベルの見出しを親とする。同じ名称の見出しが複数あっても別項目として扱う。表示用名称にはインライン要素から抽出したテキストを使い、原文の表記は変更しない。

各見出しには以下の範囲を持たせる。

- 見出し範囲: 見出し構文全体。Setext形式では下線行まで含む。
- 直接本文範囲: 見出し直後から、次のいずれかの見出しの直前まで。
- セクション範囲: 見出しから、次の同レベル以下の深さの見出しの直前まで。見出し1のブロック末尾を超えない。

位置は元の文書に対するUTF-16オフセットで保持し、VSCodeとの連携時は`TextDocument.positionAt`で変換する。日本語やサロゲートペアを含む文書でも位置がずれないようにする。

### 4.2. 配分対象

対象ブロック内の見出し2〜6を解析し、設定`timeCalculator.maxHeadingDepth`の値を上限`D`として、以下の規則で通常項目を抽出する。深さは見出しのレベルそのものを表し、見出し1からの相対的な段数ではない。

1. テキストの前後空白を除去した名前が「時間」である見出し2と、その配下を除外する。
2. 「その他」である見出し2は専用項目として扱い、通常項目から除外する。
3. 残った見出しのうちレベル2〜`D`を残し、その範囲内で子見出しを持たないものを通常項目とする。
4. レベル`D`より深い見出しは独立した配分対象にせず、上限内の祖先が配分対象であれば、その項目の内訳として本文を保持する。上限内の祖先を持たない見出しは配分対象に含めない。
5. 原文に出現する順に表示する。親見出しのパスを補助表示し、同名項目を区別する。

既定値`D = 6`では、要求の例の「案件A」はグループとなり、「作業A」「作業B」「案件B」が通常項目になる。「案件A」直下の本文があっても、グループへの配分枠は作成しない。`D = 2`に設定すると、「案件A」「案件B」が通常項目となり、「作業A」「作業B」は案件Aの内訳になる。案件Aの管理用時間行は`## 案件A`の直後に出力し、配下の見出しや本文は保持する。

レベルが飛んだ場合も同じ規則を使う。例えば見出し2の下に見出し4がある構造で`D = 3`なら、見出し2を配分対象にする。上限は配分対象の選定だけに使用し、構文解析・本文範囲の認識ではすべての深さを扱う。

見出し3以下の「時間」「その他」は通常の名称として扱い、上限の判定も行う。通常項目が0件でも、実働時間の全量をその他として適用できる。設定変更で既存の管理用時間行が配分対象外になる場合の扱いは8.1節に従う。

### 4.3. 退勤時間の取得

対象ブロックには「時間」の見出し2をちょうど1つ必要とする。その直接本文にある、文書直下の箇条書きリストの項目から時刻を取得する。

- 値は前後空白を除去し、`H:mm`または`HH:mm`形式の24時間表記として解析する。時は0〜23、分は00〜59とし、`9:00`も受け付ける。
- 時刻項目は1つだけ必要とする。非時刻のメモは無視するが、数字とコロンで始まる時刻らしい項目が形式・範囲違反ならエラーにする。
- コード・リンク・強調などを含まない、プレーンテキストのみの単一行のリスト項目を時刻入力として扱う。順序付きリスト、入れ子の項目、子見出し内の時刻は使わない。
- 時間セクションなし、同名セクション複数、時刻なし、時刻複数、不正時刻の場合は適用を禁止する。
- パネルでは退勤時刻を表示する。変更は元のMarkdownで行い、パネルを再読込する。

### 4.4. その他の扱い

「その他」の見出し2はブロックごとに最大1つとし、画面には文書内での位置にかかわらず最後に表示する。存在しなくても仮想的な行を表示する。

Markdownでは、適用時に「時間」の見出し2の直前へ配置する。既存のその他が別の位置にある場合は、その本文を含めて移動する。画面の表示順とMarkdownの配置はそれぞれこの規則に従う。

既存のその他にある本文は保持するが、その時間は常に残時間から再計算する。既存値を通常項目の合計には含めない。その他が複数ある場合、または子見出しを持つ場合は、用途を一意に決められないためエラーとする。

## 5. 拡張設定と勤務区分

`package.json`の`contributes.configuration`に以下を定義する。文書URIに対して解決した設定を使用し、複数ルートのワークスペースでも対象文書側の設定を採用する。

| キー | 型 | 既定値 | 意味 |
| --- | --- | --- | --- |
| `timeCalculator.startTime` | string | `"09:00"` | 通常勤務の始業時刻 |
| `timeCalculator.breakTimes` | string[] | `["12:00-13:00"]` | 休憩時間帯。例: `["12:00-13:00", "20:00-20:30"]` |
| `timeCalculator.amLeaveStartTime` | string | `"13:00"` | AM休暇時の始業時刻 |
| `timeCalculator.maxHeadingDepth` | integer | `6` | 配分対象とする見出しの最大深さ。2〜6を指定 |

時刻は4.3節と同じ形式とする。休憩時間はその時刻をASCIIハイフンでつなぎ、前後空白を許容する。空配列は休憩なしを表す。空文字、不正な型、範囲外の時刻、開始が終了以上の休憩を拒否する。入力形式は設定スキーマ、意味上の妥当性は拡張側で検証する。重複・重なり・隣接する休憩はエラーにせず、6.1節の規則で統合する。

`maxHeadingDepth`は整数かつ2以上6以下に制限する。文字列、小数、範囲外の値はエラーとし、設定スキーマと拡張側の両方で検証する。既定値6では従来どおり見出し2〜6を対象にし、2では案件単位、3では作業単位など、文書の構造に応じて配分の粒度を選択できる。

勤務区分の初期値は通常勤務とする。「AM休暇」を選択した場合だけ`amLeaveStartTime`を始業時刻に採用する。休憩時間の設定は両区分で共通とする。区分変更時も項目の配分値を保持し、合計と残時間を再計算する。

勤務区分と未適用の入力はパネルのセッション中だけ保持する。パネルの非表示・再表示では復元し、パネルを閉じた後やVSCodeの再起動後には復元しない。勤務区分はMarkdownへ出力しないため、再度開いた際は利用者が必要に応じて選び直す。適用済みの配分値はMarkdownの管理用時間行から復元する。

対象に関係する設定が変更されたらパネルを更新待ち状態にして適用を禁止する。「再読込」で新しい設定を取り込む。入力がある場合は破棄確認を行い、取り込み後は文書の値から初期化する。

## 6. 時間計算

### 6.1. 実働時間

内部表現はすべて整数の「分」とし、タイムゾーンや日付オブジェクトによる計算は行わない。

始業時刻を`S`、退勤時刻を`E`、各休憩を半開区間`[Bs, Be)`とする。

1. `E > S`を確認する。
2. 各休憩を勤務区間`[S, E)`と交差させる。交差しない休憩は計算から除外する。
3. 交差区間を開始順に並べ、重複・重なり・隣接を統合する。
4. 統合済み区間の長さの合計を休憩時間`B`とする。
5. 丸め前の実働時間を`Wraw = E - S - B`として求める。
6. 6.2節の規則で15分単位に丸め、配分に使用する実働時間`W`を求める。

勤務前・退勤後の休憩を差し引かず、重複区間を二重控除しない。始業・退勤時刻や個々の休憩区間は丸めず、控除後の合計を一度だけ丸める。休憩が勤務区間全体を覆う場合、`Wraw = W = 0`は有効とする。

| 始業 | 退勤 | 設定休憩 | 控除 | 実働 |
| --- | --- | --- | --- | --- |
| 09:00 | 18:00 | 12:00-13:00 | 60分 | 480分 = 8h |
| 09:00 | 20:00 | 12:00-13:00、20:00-20:30 | 60分 | 600分 = 10h |
| 13:00（AM休暇） | 18:00 | 12:00-13:00 | 0分 | 300分 = 5h |
| 09:00 | 18:00 | 12:00-13:00、12:30-13:30 | 90分 | 450分 = 7.5h |
| 09:00 | 12:30 | 12:00-13:00 | 30分 | 180分 = 3h |

### 6.2. 単位と表示

配分単位は15分とする。各項目の値は0以上かつ15の倍数の整数分だけを許可する。カウンターの1操作で15分増減し、0分からの減算は無効にする。

丸め前の実働時間`Wraw`を15で割った余りを`r`として、次の規則で丸める。

- `0 <= r <= 7`: `W = Wraw - r`として下の15分単位へ切り捨てる。`r = 0`では値を変えない。
- `8 <= r <= 14`: `W = Wraw + (15 - r)`として上の15分単位へ切り上げる。

式では`W = 15 × floor((Wraw + 7) / 15)`となる。配分合計との比較、残時間、その他には丸め後の`W`を使用する。元のMarkdownの退勤時刻や拡張設定は書き換えない。15分単位に合わないこと自体はエラーにしない。

| 始業 | 退勤 | 休憩 | 丸め前 | 端数 | 丸め後の実働時間 |
| --- | --- | --- | --- | --- | --- |
| 09:00 | 18:00 | 60分 | 480分 | 0分 | 480分 = 8h |
| 09:00 | 18:07 | 60分 | 487分 | 7分 | 480分 = 8h |
| 09:00 | 18:08 | 60分 | 488分 | 8分 | 495分 = 8.25h |
| 09:00 | 18:10 | 60分 | 490分 | 10分 | 495分 = 8.25h |
| 09:00 | 18:15 | 60分 | 495分 | 0分 | 495分 = 8.25h |
| 09:00 | 09:07 | 0分 | 7分 | 7分 | 0分 = 0h |
| 09:00 | 09:08 | 0分 | 8分 | 8分 | 15分 = 0.25h |

個別の時刻自体が15分刻みである必要はない。画面には丸め前の分数と丸めによる調整分（`W - Wraw`）を表示し、実働時間の表示が元の時刻の差と異なる理由を確認できるようにする。

画面とMarkdownでは分を60で割ったh表記とし、`0h`、`0.25h`、`0.5h`、`0.75h`、`1h`、`1.25h`のように不要な末尾の0を省く。負の残時間は`-0.25h`のように符号を付ける。

### 6.3. 合計と残時間

通常項目の配分を`Ai`とし、配分済み合計を`A = ΣAi`、残時間を`R = W - A`とする。

- `R > 0`: その他に`R`を割り当てる。
- `R = 0`: その他は0hとする。
- `R < 0`: 残時間とその他の表示を負数にし、「実働時間を超過しています」と表示する。適用は禁止する。

超過状態も確認できるよう、加算操作は実働時間を上限にしない。各操作後に再計算し、エラーを解消したら他の条件が有効であることを確認して適用を有効にする。その他を含めた適用時の総配分は必ず`W`と一致する。

## 7. 配分画面

Webviewパネルのタイトルを「作業時間の配分」とし、以下の情報を表示する。

| 領域 | 内容・操作 |
| --- | --- |
| 対象 | ファイル名と見出し1の名称 |
| 勤務区分 | 通常／AM休暇の選択 |
| 勤務情報 | 採用した始業時刻、退勤時刻、実際に控除する休憩時間 |
| 集計 | 丸め後の実働時間、丸め前の分数、調整分、通常項目への配分済み合計、残時間 |
| 通常項目 | 見出し名、親見出しのパス、減算ボタン、配分時間、加算ボタン |
| その他 | 自動計算した残時間。表示専用 |
| エラー | 原因と修正先。超過時は負の残時間も表示 |
| 操作 | 「適用」「再読込」「閉じる」 |

起動時は文書の解析結果から初期値を作成する。カウンター操作・勤務区分変更ごとに再計算して同じ画面を更新する。操作だけではMarkdownを変更せず、「適用」で反映する。

「再読込」は同じ対象ブロックを再解析し、未適用入力を破棄する。入力がある場合は破棄確認を行う。元の見出し行が編集・削除されて対象を一意に追跡できない場合は、カーソルを置いてコマンドを再実行するよう案内する。見出し名だけをキーにして別のブロックへ切り替えない。「閉じる」は未適用入力を破棄してパネルを閉じる。

適用中は入力と再適用を無効にする。成功後はパネルを開いたまま新しい文書バージョンと解析結果を取り込み、現在の勤務区分を保持して再表示する。変更がない再適用では文書編集やUndo履歴を追加しない。

ボタンには項目名を含むアクセシブルなラベルを付け、キーボードで操作可能にする。VSCodeのテーマ色を使用し、エラーを色だけで伝えない。

## 8. Markdownへの反映

### 8.1. 管理用時間行

各配分対象の直接本文に、以下の形式で箇条書きを1行出力する。

```md
- 作業時間: 1.25h <!-- time-calculator:duration -->
```

マーカーは拡張が管理する行を識別するためのものである。通常の箇条書き、同じ「作業時間」という文字を含むユーザーのメモ、マーカーのない過去の時間行は自動削除・更新しない。

管理用時間行は、直接本文内の文書直下の箇条書き項目で、上記マーカーを行末に持つ単一行だけを対象にする。コード・引用・入れ子の箇条書きに書かれたマーカーは無視する。正規形式の非負の十進数hを分へ変換し、15の倍数かを確認する。指数表記、負数、無限値、空値は受け付けない。

通常項目の管理用時間行が1つなら初期値として復元し、0個なら0hとする。同じ項目に複数ある場合や、マーカー付きの値が不正な場合は適用を禁止する。その他の行も形式と重複を検証するが、数値は初期配分として使わず再計算する。

現在の配分対象でない通常見出し（グループとなる親見出し、最大深さを超える見出し）にある管理行は集計対象にしない。これらの管理行が残っている場合は二重計上を招くため、手動で削除・移動するか、最大深さの設定を戻すよう案内して適用を禁止する。深さ設定の変更による既存配分の合算や振り分けは自動では行わない。

### 8.2. 追加・更新規則

- 管理用時間行がある場合は、その行だけを新しい値で置換する。
- ない場合は見出し構文の直後に挿入する。Setext形式では下線行の後とする。
- 新規行の前後には空行を確保し、既存本文・コードブロック・リストと分離する。既存の本文を再整形しない。
- 項目の本文末尾が未終了のコードブロックなどでも、見出し直後への挿入により管理行が取り込まれない位置に置く。
- 対象ブロック以外、時間セクション、既存のメモの内容、見出しの表記は変更しない。その他のセクションの位置は8.3節に従って変更する。
- 文書のLF／CRLFを維持する。末尾への挿入に改行が必要な場合だけ補い、文書全体の改行を正規化しない。
- 差分を元の文書位置に対して生成し、範囲の重なりを検証する。同位置の挿入は1つにまとめる。
- すべての差分をテキスト編集だけの1つの`WorkspaceEdit`にまとめて適用し、通常のUndo操作で一括して取り消せるようにする。

文書全体をASTから再シリアライズせず、必要箇所だけを編集する。同じ配分で繰り返し適用しても、管理行やその他の見出しは増えない。

### 8.3. その他の出力

| 既存の`## その他` | 残時間 | 適用内容 |
| --- | --- | --- |
| なし | 正 | `## 時間`の直前に見出しと管理用時間行を追加 |
| なし | 0 | 見出しを追加しない |
| あり | 正または0 | 本文を保持し、管理用時間行を追加または更新して`## 時間`の直前へ配置 |
| 任意 | 負 | 適用しない |

新規作成時は、対象ブロックの「時間」の見出し2の開始位置に、前後の空行を確保して挿入する。既存のその他が「時間」の直前にない場合は、見出しからセクション末尾までの本文を管理用時間行の更新とともに移動する。元の位置からの削除と移動先への挿入は同じ編集計画に含める。既に直前にある場合は移動しない。

移動時もユーザーのメモと見出しの表記は保持し、時間セクションの本文は変更しない。残時間0hで既存のその他を更新する場合も、同じ配置規則に従う。差分適用後の文字列を事前解析し、その他が時間の直前の見出し2として認識され、出力した管理行が意図したセクションに属することを確認する。構造が成立しない場合は編集せず、構文の修正を求める。

要求仕様の`# 20261028`に対し、始業09:00、休憩12:00〜13:00、退勤18:00、作業A=2h、作業B=3h、案件B=1.5hとした場合は、その他が1.5hとなる。

## 9. 検証と文書競合

### 9.1. エラー処理

| 状況 | 動作・修正先 |
| --- | --- |
| 対象を選択できない | VSCodeの通知でMarkdownの対象見出しへカーソルを置くよう案内 |
| 時間セクション・退勤時刻が不正 | 配分画面に理由と該当位置を表示し、Markdownの修正を案内 |
| 設定が不正 | 該当する設定キーと理由を表示 |
| 退勤が始業以前 | 同日内の勤務になるよう時刻・勤務区分の修正を案内 |
| 配分が超過 | 残時間を負数で表示。カウンターは操作可能なまま適用禁止 |
| その他が重複・子見出しを持つ | 対象セクションの整理を案内 |
| 管理行が重複・不正・配分対象外の見出しに存在 | 該当見出しと行、必要に応じて最大深さの設定の修正を案内 |
| 出力後のMarkdown構造が不正 | 編集を行わず、構文の修正を案内 |
| 文書・設定の変更を検出 | 更新待ち状態にし、再読込を案内 |
| 対象文書が閉じられた | 適用禁止。再度文書を開いてコマンドを実行するよう案内 |
| 編集APIが失敗・書き込み不可 | 入力を保持し、反映できなかったことを通知 |

いずれのエラーでも無効な内容は文書へ反映しない。入力・構造の問題は回復可能なエラーとして扱い、Extension Hostに未処理の例外を伝播させない。

### 9.2. 競合の防止

読込時に対象文書のURI、`TextDocument.version`、対象ブロックの範囲・本文、設定のスナップショットを保持する。`onDidChangeTextDocument`と`onDidChangeConfiguration`で変更を監視する。

元文書のどこかが変更された場合、対象外のブロックの編集やUndoであっても保守的に更新待ち状態にする。対象の見出し行が維持されている場合だけ、変更イベントの位置情報から範囲を追跡して再読込に使う。追跡不能なら再選択を必要とする。

適用処理では、次の順に再検証する。

1. 対象文書が開いており、スナップショットの文書バージョン・設定と一致することを確認する。
2. 元文書を再解析し、項目ID・管理行・入力値・計算結果を検証する。
3. 差分と適用後の文字列を構築し、8章の構造条件を満たすか事前解析する。
4. 文書バージョンを再確認し、確認から編集API呼び出しまで非同期処理を挟まずに`workspace.applyEdit`を呼び出す。
5. 戻り値が成功の場合だけ完了を表示し、最新の文書を読み直す。失敗時は成功表示を出さずに入力を保持する。

適用中に自分の編集から発生する文書変更イベントと、それ以外の変更を区別する。外部変更が混在した場合は更新待ちに戻し、古い解析結果で次の適用を許可しない。VSCodeの編集API呼び出しは文書をロックするものではないため、無条件に競合が起きないとは扱わない。

## 10. 内部構成

TypeScriptで実装し、VSCode依存部分と純粋な解析・計算・差分生成処理を分離する。

| モジュール案 | 責務 |
| --- | --- |
| `src/extension.ts` | コマンド登録、パネル起動、購読の破棄 |
| `src/config/settings.ts` | 文書単位の設定取得、設定値の検証 |
| `src/markdown/parser.ts` | Markdown構文解析、見出し・時間・管理行の抽出 |
| `src/domain/models.ts` | 範囲、項目、時間、診断結果、セッションの型定義 |
| `src/domain/timeCalculator.ts` | 休憩区間の統合、実働時間の計算・丸め、配分合計・残時間の計算 |
| `src/markdown/editPlanner.ts` | 追記・更新差分と適用後文字列の生成、構造検証 |
| `src/application/allocationSession.ts` | 対象固定、入力状態、文書競合、適用処理の制御 |
| `src/webview/panel.ts` | Webviewの生成、メッセージ検証と送受信 |
| `webview/` | 画面、イベント処理、テーマ対応のスタイル |
| `src/test/unit/` | Vitestの単体テスト |
| `src/test/integration/` | VSCode Extension Hostで動かすMochaの統合テスト |

主要データは次のとおりとする。

| データ | 主な内容 |
| --- | --- |
| `DayBlock` | 見出し1の名称、原文範囲、見出しツリー、退勤分数、診断結果 |
| `WorkItem` | セッション内ID、名称、親パス、見出し・本文範囲、既存管理行、配分分数 |
| `WorkSettings` | 通常始業分数、AM休暇始業分数、休憩区間配列、見出しの最大深さ |
| `CalculationResult` | 始業・退勤・休憩、丸め前・丸め後の実働分数、調整分、通常配分合計・符号付き残時間、適用可否 |
| `AllocationSession` | 文書URI、文書バージョン、設定、対象範囲、勤務区分、項目、画面状態、状態リビジョン |
| `EditPlan` | 元文書上の編集範囲と置換文字列、適用後の文字列 |

項目IDは見出し名だけから作らず、読込世代と見出しの位置・出現順で一意にする。文書や設定の再読込時はIDを再発行し、前の世代の画面メッセージを拒否する。その他は通常項目のID集合から分離する。

画面状態は`loading`、`ready`、`invalid`、`stale`、`applying`、`disposed`で管理する。解析エラー・設定エラー・超過などは`invalid`とし、エラー種別に応じて修正可能な操作を残す。適用できるのは`ready`だけとする。

### 10.1. Webview通信

| 方向 | メッセージ | 内容 |
| --- | --- | --- |
| Webview → 拡張 | `ready` | 初期状態の要求 |
| Webview → 拡張 | `adjust` | 読込世代、状態リビジョン、項目ID、増減方向 |
| Webview → 拡張 | `changeWorkMode` | 読込世代、状態リビジョン、通常／AM休暇 |
| Webview → 拡張 | `apply` | 読込世代、状態リビジョンに対応する状態の適用要求 |
| Webview → 拡張 | `reload` / `close` | 再読込／終了要求 |
| 拡張 → Webview | `state` | 世代、リビジョン、表示データ、エラー、適用可否の全体 |
| 拡張 → Webview | `applyResult` | 適用の成否と表示メッセージ |

配分値と計算結果の正本は拡張側に置く。受信メッセージの型、項目ID、世代、リビジョンを実行時に検証し、画面から渡された合計・適用可否は信用しない。拡張側で操作を直列処理し、状態の更新ごとにリビジョンを増やす。画面は応答まで変更操作を待機させ、古いリビジョンの操作は実行せず最新状態を返す。

Webview再生成時は`ready`に対して拡張側のセッションを再送する。パネル破棄時は関連するイベント購読とセッションも破棄する。

### 10.2. 安全性と実装規約

- Markdown本文は実行せず、見出し名は`textContent`などでテキストとして表示する。
- Webviewは必要なローカルのスクリプトとスタイルだけを読み込み、CSPと`localResourceRoots`で読み込み先を制限する。外部通信は行わない。
- 文書編集は拡張側の検証済み差分だけから生成し、Webviewから任意のURI・編集範囲を指定できないようにする。
- TypeScriptはGoogle TypeScript Style Guideに従う。新しい関数・クラスには概要コメント、テストには概要と目的のコメントを付ける。

## 11. 検証計画

### 11.1. 単体テスト（Vitest）

VSCodeに依存しない処理を対象に、以下の境界条件と不変条件を検証する。

| 分類 | 主なケース・確認事項 |
| --- | --- |
| ブロック選択 | 先頭・中間・末尾の見出し1、次の見出し行、前書き、同名の日見出し |
| 構文解析 | ATX／Setext、階層の飛び、同名項目、親と末端、コード・引用・リスト・HTML内の疑似見出し |
| 見出しの最大深さ | 上限2・3・6での項目抽出、上限での親への配分、上限超過の子見出しの保持、上限内の祖先なし、階層の飛び |
| 特殊見出し | 時間なし・重複、時間配下の除外、その他なし・既存・重複・子見出し、通常項目0件 |
| 時刻解析 | 9:00、00:00、23:59、24:00、18:60、時刻複数、不正な時刻らしい項目、入れ子の時刻除外 |
| 設定検証 | 型違い、空文字、休憩なし、不正休憩、通常／AM休暇の切替、最大深さの1・7・小数・文字列の拒否 |
| 休憩計算 | 重複・包含・隣接、勤務外、勤務境界での切り詰め、勤務全体を覆う休憩、6.1節の計算例 |
| 実働時間の丸め | 端数0・7・8・14分、7分→0分・8分→15分、休憩控除後に一度だけ丸めること、6.2節の計算例 |
| 配分計算 | 0h、0.25hの増減、0未満の拒否、全量配分、超過と復帰、丸め後の実働時間による残時間計算、h表示 |
| 管理行 | 既存値の復元、マーカーなしの保持、配分対象外の管理行、深さ設定変更後の既存値の扱い、重複・不正値、その他の値の再計算 |
| 差分生成 | 見出し直後の追加、既存行更新、時間の直前へのその他新設・移動、0h時の条件、移動時の本文保持、出力構造の検証 |
| 原文保持 | LF／CRLF、末尾改行なし、日本語・絵文字、対象外の日・本文が変わらないこと |
| 冪等性 | 同じ値で再適用して差分が0件。値を変えても見出し・管理行が増えないこと |
| 通信・状態 | 不正メッセージ、未知ID、古い世代・リビジョン、連続操作、適用中の再要求の拒否 |

有効な計算では`丸め前の実働 >= 0`、`丸め後の実働 >= 0`、`通常項目合計 + その他 = 丸め後の実働`、全配分が15分単位、丸めの調整分が-7〜+7分であることを確認する。生成後のMarkdownを再解析し、意図した項目へ値を復元でき、その他を出力する場合は時間の直前に配置されることも確認する。

### 11.2. 統合テスト（Mocha）

VSCode Extension Host上で、以下を検証する。

1. Markdownの対象位置からコマンドを実行し、正しいブロックのセッションとパネルを生成できる。
2. 受信メッセージによるカウンター操作・AM休暇切替がセッションと表示データに反映される。
3. 適用により対象ブロックだけが更新され、再適用で行が増えず、1回のUndoで適用前に戻る。
4. 超過・設定不正・解析不正・構造検証失敗の場合、文書が変更されない。
5. 開いている未保存の編集を解析し、文書URIに対応した設定を使う。
6. 表示中に文書を編集・Undoした場合や設定を変更した場合、古いセッションから適用できない。
7. 文書を閉じた場合、編集APIが失敗した場合、連続して適用を要求した場合に誤って成功扱いしない。
8. 再読込・別ブロックへの切替・パネル破棄で、入力の破棄条件とイベント購読の後始末が正しい。
9. 最大深さを変更して再読込すると配分対象が変わる。配分対象外の管理行がない文書では上限で選ばれた見出しに時間を出力でき、配下の見出し・本文が保持される。対象外の管理行が残る文書では修正を案内し、適用できない。
10. 端数7分・8分の実働時間で、丸め前・丸め後・調整分が表示され、丸め後の合計で適用できる。
11. その他が新規・既存のどちらでも時間の直前に配置され、移動後もメモが保持され、1回のUndoで元の位置・内容へ戻る。

テーマ表示、キーボード操作、スクリーンリーダー向けラベル、負数・エラー表示、パネルの非表示からの復帰は手動確認も行う。

### 11.3. 要求の動作例による受入確認

最大深さを既定値6として要求仕様のMarkdownを使用し、次を確認する。8項目目以降は、各条件に応じて退勤時刻・設定・本文を変更する。

1. `# 20261028`を選ぶと、作業A・作業B・案件B・その他の4行が表示され、案件Aは配分行にならない。
2. 始業09:00、休憩12:00〜13:00で、実働8h・配分済み0h・その他8hとなる。
3. 作業A=2h、作業B=3h、案件B=1.5hにすると、各操作で更新され、その他1.5hとなる。
4. 適用すると8.4節の結果になり、その他が時間の直前に追加され、`# 20261029`の内容は変わらない。
5. 通常項目の合計を8.25hにすると、残時間・その他が-0.25hになり、適用できない。
6. 合計8hならその他は0h。まだその他の見出しがなければ新設せず、既にあれば0hに更新する。
7. AM休暇へ切り替えると実働5hとなり、配分を5h以内に調整するまで超過エラーとなる。
8. 退勤18:07・通常勤務なら実働487分を480分へ切り捨て、18:08なら488分を495分へ切り上げる。配分済み8hの場合、その他はそれぞれ0h・0.25hとなる。
9. 管理用時間行のない原文で最大深さを2にすると、案件A・案件B・その他の3行が表示される。適用時は案件Aの直後に管理行が追加され、作業A・作業Bの見出しと本文は保持される。
10. その他を時間より後に置いた文書へ適用すると、メモを含むその他のセクションが時間の直前へ移動する。再適用で重複や再移動が発生しない。
